## 1. 项目是什么

MonadForge（太初玄鼎）是 [anima_lora](https://github.com/sorryhyun/anima_lora) 的深度改进分支：

- **WebUI 工作台**：FastAPI + Vue3，浏览器里完成数据浏览、预处理、训练、监控、合并
- **训练 daemon**：后台守护进程（127.0.0.1:8765），串行任务队列，WebUI 关闭训练不中断
- **核心能力**：Anima 扩散模型的 LoRA 系列训练（普通 LoRA / OrthoLoRA / T-LoRA / HydraLoRA / LoKr 等）
- **检查点格式**：训练结果保存为普通 LoRA（safetensors），可合并进 DiT

## 2. 环境要求与 AutoDL 选机

### 2.1 官方系统要求

| 项目 | 要求 |
|---|---|
| GPU | NVIDIA Volta 及以上，推荐 Ampere+（RTX 3000 / A100 / RTX 5060 Ti / 5090） |
| 驱动 | 项目 README 写 ≥ 595（实测 580.76 也能跑通 cu132，以自检为准） |
| CUDA Toolkit | 13.2（用于 torch.compile 的 ptxas；不编译可放宽） |
| Python | 3.13（由 uv 自动管理，无需手动装） |
| 显存 | 8GB 起，推荐 16GB+；5090 32GB 很宽裕 |

### 2.2 AutoDL 选机建议

- **GPU**：RTX 5090 32GB 单卡即可，训练速度约 1.5~2.8 it/s
- **镜像**：`PyTorch / 2.8.0 / 3.12(ubuntu22.04) / 12.8` 即可
  - 项目会用 `uv sync` 自建 Python 3.13 + torch 2.12(cu132)，**镜像自带环境不会被用到**
- **数据盘**：勾选“需要扩容”，建议 **100GB 以上**（环境 + 模型 + 数据集 + 检查点 ≈ 25GB 起）
- **计费**：按量计费即可；关机只收少量存留费，数据盘保留

### 2.3 重要概念：系统盘 vs 数据盘

- `/root`（系统盘，30GB）：**关机重置会丢**，别放重要东西
- `/root/autodl-tmp`（数据盘）：**关机保留**，放仓库、环境、模型、数据集、检查点
- 换宿主机时数据盘可能不跟过来 → 重启后先验证数据（见 4.3）

## 3. 首次部署（一次性）

### 3.1 克隆仓库（建议放数据盘）

```bash
cd /root/autodl-tmp
git clone --depth 1 https://github.com/LingyeSoul/MonadForge.git
cd MonadForge
```

- GitHub 直连失败（`RPC failed; curl 56`）时：
  - 开 AutoDL 学术加速：`source /etc/network_turbo`（当前终端有效，会加速 github/huggingface）
  - 或镜像：`git clone --depth 1 https://ghproxy.com/https://github.com/LingyeSoul/MonadForge.git`
  - 或下 zip：`wget -O main.zip https://ghproxy.com/https://github.com/LingyeSoul/MonadForge/archive/refs/heads/main.zip` 再解压

### 3.2 一键安装

```bash
cd /root/autodl-tmp/MonadForge
chmod +x setup-linux.sh start-webui-linux.sh
./setup-linux.sh
```

脚本会完成：

1. 安装 uv
2. `uv sync`：下载 Python 3.13、torch 2.12+cu132、flash-attn 等约 204 个包（**耗时较长，失败会自动重试 3 次**）
3. 若系统无 Node，下载便携版 Node v24
4. 构建 Vue 前端（输出到 `webui/frontend/dist/`）

> 小提示：`npm: command not found` 不用管，脚本会自带 Node。
> 若 `uv sync` 很慢，可先 `unset http_proxy https_proxy all_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY` 关掉学术加速再跑（加速会拖慢 pip 源）。

### 3.3 GPU 自检

```bash
cd /root/autodl-tmp/MonadForge
source .venv/bin/activate
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.get_device_name(0), torch.cuda.is_available())"
```

应输出类似：`2.12.0+cu132 13.2 NVIDIA GeForce RTX 5090 True`。

若报 “CUDA driver version is insufficient”：

- 换一台驱动更新的 AutoDL 主机
- 或走仓库自带 V100 兼容方案（`setup-v100-linux.sh`，torch 2.10+cu129，5090 也能用但性能打折）

### 3.4 下载模型

```bash
export HF_ENDPOINT=https://hf-mirror.com   # 国内镜像
hf auth login                              # 粘贴 Access Token（不显示字符，正常）
python tasks.py download-models
```

说明：

- 基础模型来自 `circlestone-labs/Anima`（约 5.6GB）：DiT + Qwen3-6B 文本编码器 + QwenImage VAE
- 若提示 gated/授权，先到 https://huggingface.co/circlestone-labs/Anima 同意许可
- `download-models` 还会拉 SAM3（需单独申请，**失败可忽略**）、MIT、PE、Tagger 等
- token 无效不影响 Anima 下载（公开仓库自动匿名），但会影响 gated 组件

### 3.5 修正模型路径（关键！）

仓库自带的 `configs/base.toml` 里是作者本机路径，必须改成自己的：

```bash
cd /root/autodl-tmp/MonadForge

sed -i 's|^pretrained_model_name_or_path = .*|pretrained_model_name_or_path = "models/diffusion_models/anima-base-v1.0.safetensors"|' configs/base.toml
sed -i 's|^qwen3 = .*|qwen3 = "models/text_encoders/qwen_3_06b_base.safetensors"|' configs/base.toml
sed -i 's|^vae = .*|vae = "models/vae/qwen_image_vae.safetensors"|' configs/base.toml

grep -n "models/" configs/base.toml
```

三行都应指向 `models/...`。改完 WebUI Config 页 **Reload** 后 Paths 区会显示正确路径。

## 4. 日常重启启动（最常用）

### 4.1 开机

1. AutoDL 控制台 → 实例列表 → **开机**
2. **确认是 GPU 模式**（显示 RTX 5090），不要用“无卡模式”
3. 记下实例详情里最新的 **SSH 端口**（每次开机可能变）

### 4.2 连接云端终端

方式 A（推荐网页端）：控制台 → JupyterLab → 左侧 **Terminal**

方式 B（本地 SSH）：

```powershell
ssh -p 端口号 root@connect.bjb1.seetacloud.com
```

判断标准：

- 云端终端提示符：`root@autodl-container-xxx:~#`
- 本地 PowerShell 提示符：`PS C:\Users\Mayn>`
- **Linux 命令只能在云端终端跑**；scp/端口转发只能在本地 PowerShell 跑

### 4.3 验证数据还在

```bash
ls /root/autodl-tmp/MonadForge/models/diffusion_models
ls /root/autodl-tmp/MonadForge/image_dataset/<你的数据集目录> | wc -l
```

- 第一条应显示 `anima-base-v1.0.safetensors`
- 第二条应等于「图片数 × 2」（图 + txt）
- 若为空 → 换了宿主机，联系重部署

### 4.4 启动 WebUI

```bash
cd /root/autodl-tmp/MonadForge
source .venv/bin/activate
export ANIMA_DAEMON_HOST_WEBUI=0
nohup .venv/bin/python -m webui --host 0.0.0.0 --port 8000 > webui.log 2>&1 &
sleep 8
cat webui.log
```

看到 `Uvicorn running on http://0.0.0.0:8000` 即成功。

参数说明：

| 参数 | 作用 |
|---|---|
| `ANIMA_DAEMON_HOST_WEBUI=0` | 禁止 daemon 再拉起一个 127.0.0.1 的 WebUI，避免端口冲突 |
| `--host 0.0.0.0` | 让 WebUI 可被端口转发访问（AutoDL 自定义服务也需要） |
| `nohup ... &` | 后台运行，SSH 断开不中断 |

### 4.5 本地端口转发

本地 PowerShell 新开窗口（**保持开着**）：

```powershell
ssh -CNg -L 8000:127.0.0.1:8000 -p 端口号 root@connect.bjb1.seetacloud.com
```

浏览器打开 **http://127.0.0.1:8000**

> 为什么不推荐 AutoDL“自定义服务”：WebUI 有同源校验（只放行 localhost origin），代理域名下提交训练会被 403，所以 SSH 转发最稳。

## 5. 数据集准备（图 + 标签）

### 5.1 目录结构

```
/root/autodl-tmp/MonadForge/image_dataset/
└── 12_danbaofan_omuless/     ← 每个画风一个子目录，名字随意
    ├── 0000.png
    ├── 0000.txt
    ├── 0001.png
    └── 0001.txt
```

- 图与 txt **同名同目录**，训练按文件名配对
- 子目录可嵌套，预处理/训练会递归扫描（`recursive = true`）
- 文件夹名里的 `N_` 前缀**不会**被当成重复次数（`repeat_by_folder_name: False`），重复次数由配置 `num_repeats` 控制

### 5.2 标签格式

每张图配一个 `.txt`，Danbooru 风格，逗号分隔，**触发词放最前面**：

```
@danbaofan_omuless, 1girl, solo, pink hair, long hair, looking at viewer, hanfu, moon, night, butterflies
```

- 触发词用 `@画师名` 格式（项目对 `@` 开头标记有保护，打乱标签时不拆散）
- 内容 tag 尽量简短；长描述句可有可无（本项目既有 tag 也有描述句也正常）
- 风格 LoRA 可以只写触发词不写内容 tag（模型从图片学画风）

### 5.3 数据质量（画风还原的关键）

- **画风统一**：同一画师、同一时期；混入其他画风会稀释风格
- **数量**：风格 LoRA 建议 30~200 张；15~25 张能训但要加 epochs；过少易过拟合
- **删掉带水印/文字/低清的图**（水印会被学进去）
- 分辨率/长宽比可以杂（自动分桶），但差异太大会导致 torch.compile 报错（见 12.4）

### 5.4 上传

本地 PowerShell：

```powershell
scp -P 端口号 -r "C:\本地文件夹" root@connect.bjb1.seetacloud.com:/root/autodl-tmp/MonadForge/image_dataset/
```

云端整理 + 校验：

```bash
cd /root/autodl-tmp/MonadForge
mv "/root/autodl-tmp/MonadForge/image_dataset/本地文件夹名" image_dataset/<目标名>

ls image_dataset/<目标名> | wc -l
grep -h "^@触发词" image_dataset/<目标名>/*.txt | head -1
```

### 5.5 批量处理本地标签（Windows）

把触发词加到所有 txt 开头（本地 PowerShell，需要授权）：

```powershell
$dir='C:\你的文件夹'
$utf8NoBom = New-Object System.Text.UTF8Encoding($false)
Get-ChildItem -LiteralPath $dir -Filter *.txt | ForEach-Object {
  $c = [System.IO.File]::ReadAllText($_.FullName)
  $c = $c -replace '@触发词\s*,?\s*','' -replace '@him\w*\s*,?\s*',''
  $c = $c.Trim()
  if (-not $c.StartsWith('@触发词')) { $c = '@触发词, ' + $c }
  [System.IO.File]::WriteAllText($_.FullName, $c, $utf8NoBom)
}
```

## 6. 预处理（Preprocess 页面详解）

### 6.1 页面结构（从上到下）

1. **预处理运行（Preprocess Run）**：选择缓存运行；`自动（当前来源与配置）` = 不锁定任何 run
2. **流水线状态（Pipeline Status）**：Resized / Latents / TE / PE / Masks / Cond Resized 的计数
3. **数据集路径（Dataset Paths）**：源图片目录、缩放后目录、缓存目录等
4. **预处理设置（Preprocessing Settings）**：分辨率档、SAM/MIT 掩码、标签打乱等（可折叠）
5. **操作卡片**：执行缩放（Run Resize）、缓存 VAE（Cache VAE）、缓存 TE（Cache TE）

### 6.2 正确流程（三步，顺序不能乱）

```text
Run Resize → Cache VAE → Cache TE
```

- **源图片目录**填：`image_dataset/<你的数据集子目录>`（直接指向装着图片和 txt 的文件夹）
- 每步等 Tasks 页 success 再进行下一步
- 完成标准：**Resized / Latents / TE 都等于图片数**

### 6.3 路径怎么改

界面能改就界面改（Automatic 模式下字段解锁）。界面锁死时用命令：

```bash
cd /root/autodl-tmp/MonadForge
sed -i 's|^source_image_dir = .*|source_image_dir = "image_dataset/<目标目录>"|' configs/preprocess.toml
if [ -f configs/custom/preprocess.toml ]; then
  sed -i 's|^source_image_dir = .*|source_image_dir = "image_dataset/<目标目录>"|' configs/custom/preprocess.toml
fi
grep -n "^source_image_dir" configs/preprocess.toml
```

然后 WebUI **Ctrl+F5 刷新**。

### 6.4 run 机制与常见坑

- 预处理结果有两种存放方式：
  - **run 模式**：`post_image_dataset/runs/<来源>-<hash>/...`（WebUI 选中某个 run 时）
  - **普通模式**：`post_image_dataset/resized` + `post_image_dataset/lora`（Automatic 时）
- 训练固定使用**当前选中的 run**；如果下拉框里是旧的 run（如 `image_dataset-4c8ef0f84383`），
  训练就会用旧数据 → **点输入框右侧的 X 清掉 run 选择**，切回 Automatic
- **换数据集时必须清掉旧缓存**，否则新旧数据混在一起（典型症状：图片数变成 51+22=73 或 19+19=38）：

```bash
cd /root/autodl-tmp/MonadForge
mv post_image_dataset/resized post_image_dataset/resized_old 2>/dev/null
mv post_image_dataset/lora post_image_dataset/lora_old 2>/dev/null
```

- 验证数量（只看图片文件，别数子文件夹）：

```bash
find post_image_dataset/resized -maxdepth 1 -type f \( -name '*.png' -o -name '*.jpg' \) | wc -l
ls post_image_dataset/resized | grep -c "^子文件夹名$" || true
```

- 标签改动后必须**重跑 Cache TE**（文本缓存不会自动更新）

### 6.5 常见状态解读

- 全 0：还没跑，正常
- 某个数字大于图片数：混了旧数据，清缓存重跑
- 转圈/等待：任务在后台跑，Tasks 页看进度

## 7. 配置详解（Config 页面）

### 7.1 顶部选择

- **Method**：`lora`（普通 LoRA）/ `tlora`（T-LoRA）等
- **Variant**：具体变体
  - `LoRA`：普通 LoRA（最稳基线）
  - `T-LoRA + OrthoLoRA`：T-LoRA（推荐进阶）
  - 带 `(8GB hardware)` 的是低显存版，5090 不需要
- **Preset**：`default`

### 7.2 关键字段（按区块）

**Paths（路径）**

- `pretrained_model_name_or_path` / `qwen3` / `vae`：应指向 `models/...`（只读，来自 base.toml）
- `resized_image_dir`：`post_image_dataset/resized`
- `lora_cache_dir`：`post_image_dataset/lora`
- `output_name`：输出名（可编辑），如 `iotaectoplasm_tlora_V1`

**Training（训练）**

- `network_dim` / `network_alpha`：LoRA 维度/缩放。风格类常用 64~128；T-LoRA 参考配方 32
- `learning_rate`：风格类 5e-5 ~ 1e-4
- `max_train_epochs`：风格类 12~50；图少可多
- `save_every_n_epochs`：每 N 个 epoch 存检查点（默认 2）
- `use_shuffled_caption_variants`：标签打乱增强泛化

**Performance / Other（多为只读，来自 base.toml）**

- `batch_size`：1（图少长宽比杂时必须 1）
- `gradient_accumulation_steps`：1 或 4
- `gradient_checkpointing`：显存紧张时 true
- `torch_compile`：**建议 false**（本项目对杂分辨率会编译报错）
- `attn_mode`：`flash` 或 `sdpa`（本项目自动兼容）
- `mixed_precision`：`bf16`（5090 推荐）或 `fp16`
- `timestep_sampling`：`shift` / `sigmoid`

**Preview Sampling（预览）**

- `sample_prompts`：预览提示词文件 `configs/custom/sample_prompts.txt`
- `sample_every_n_epochs`：每 N 个 epoch 出预览（默认 2）
- `sample_decode_inline`：**必须 true** 才会直接出 PNG（false 只存 .pt latent，界面看不到图）

### 7.3 配置文件的优先级

实际生效链：`configs/base.toml → configs/presets.toml[default] → 变体文件`

**关键**：WebUI 保存的自定义变体在 `configs/custom/variants/<变体名>.toml`，它**优先于** `configs/gui-methods/<变体名>.toml`。
训练日志里 `origin=configs/custom/variants/tlora.toml` 就说明用的是自定义文件。

所以改参数时，**两个文件都要改**（或直接改 custom 那个）：

```bash
cd /root/autodl-tmp/MonadForge
F=configs/custom/variants/tlora.toml    # 优先
F2=configs/gui-methods/tlora.toml       # 兜底
```

### 7.4 只读字段怎么改（sed 命令）

界面锁定的字段来自 base.toml，用 sed 改：

```bash
B=configs/base.toml

# 学习率调度
sed -i 's|^lr_scheduler = .*|lr_scheduler = "constant_with_warmup"|' $B
sed -i 's|^lr_warmup_steps = .*|lr_warmup_steps = 0.1|' $B

# 优化器 / 精度
sed -i 's|^optimizer_type = .*|optimizer_type = "AdamW8bit"|' $B
sed -i 's|^mixed_precision = .*|mixed_precision = "fp16"|' $B

# 训练相关
sed -i 's|^gradient_accumulation_steps = .*|gradient_accumulation_steps = 4|' $B
sed -i 's|^gradient_checkpointing = .*|gradient_checkpointing = false|' $B
sed -i 's|^torch_compile = .*|torch_compile = false|' $B
sed -i 's|^seed = .*|seed = 3130051245|' $B

# 采样
sed -i 's|^timestep_sampling = .*|timestep_sampling = "shift"|' $B
sed -i 's|^discrete_flow_shift = .*|discrete_flow_shift = 0.9|' $B

# batch_size 在 [[datasets]] 下（行首无缩进）
sed -i 's|^batch_size = .*|batch_size = 1|' $B
```

**特别注意两个缩进坑：**

- `num_repeats` 在 `[[datasets.subsets]]` 下，**行首有空格**，必须用带空白匹配的 sed：
  ```bash
  sed -i 's|[[:space:]]*num_repeats = .*|num_repeats = 8|' configs/base.toml
  ```
- `batch_size` 行首无缩进，`^batch_size` 能匹配

### 7.5 预览提示词文件

```bash
cat > /root/autodl-tmp/MonadForge/configs/custom/sample_prompts.txt <<'EOF'
@触发词, 1girl, 题材描述
EOF
```

每行一条提示词 = 一张预览图。**训练启动时读取**，改完必须重新 Train。

> 测试画风时少用 `score_9, photorealistic, extremely detailed` 这类“高分词”，
> 它们会把画面拉向平滑完美，压制厚涂/笔触感。

## 8. 开始训练

### 8.1 点击流程

1. Config 页确认 Method / Variant / Preset
2. 点 **Reload**（让界面读到最新文件）
3. 点绿色 **Train**
4. 若弹窗 “Checkpoint Found（发现可恢复检查点）”：
   - 同一批数据继续训 → **Resume**
   - 换过数据/参数 → **Start Fresh（从头开始）**（多数情况选这个）
5. 日志/仪表盘确认数据与步数

### 8.2 日志必须确认的三件事

```text
image_count: 19            ← 图片数（必须等于你的图数）
num_repeats: 8             ← 重复次数
max_train_steps=456        ← 总步数 = 图片数 × repeats ÷ grad_accum × epochs
```

典型错误：

- `image_count` 比图数多 → 缓存混了旧数据（见 6.4）
- `num_repeats: 1` → sed 缩进坑（见 7.4）
- `max_train_steps=1100`（22 图）却期望 8800 → repeats 没生效

## 9. 监控与曲线解读

### 9.1 Dashboard 页面

- 进度环：步数 / 总步数、epoch
- Loss / LR / Speed 卡片
- GPU 占用、显存、温度
- 训练预览图（Sample Previews）
- Loss Curve / LR Curve

### 9.2 曲线怎么看

**Loss 曲线**

- 起步 0.10~0.16 剧烈波动 → 正常（warmup + 起步阶段）
- 断崖式下跌后进入 0.03~0.08 平台 → 收敛良好
- 一直不降 / 持续上升 → 数据或参数问题
- 结尾突然飙升 → 可能过拟合或数据混入

**LR 曲线**

- `constant_with_warmup`：先爬坡到设定值，然后一条直线
- `cosine`：先爬坡到峰值，再余弦下降到 0
- 出现锯齿（多次爬坡重来）→ 任务被重启过（中断后重训），不影响最终结果但说明跑得不干净

### 9.3 预览图判断标准

- 第 2~4 epoch：内容大致对，风格弱 → 正常
- 第 6~10 epoch：线条/上色/笔触开始向目标画风靠 → 方向对
- 构图开始复刻训练图 → 过拟合信号，减 epochs / 降 lr

## 10. 参数调优

### 10.1 普通 LoRA vs T-LoRA

| | 普通 LoRA | T-LoRA |
|---|---|---|
| 有效 rank | 全程固定 | 高噪声满 rank，低噪声降到 min_rank |
| 训练开销 | 固定 | 低 rank 阶段略省 |
| 检查点 | 普通 LoRA | 普通 LoRA（mask 只影响训练） |
| 适用 | 最稳基线 | 减少过拟合，细节更高效 |

建议：先跑普通 LoRA 做基线，再跑 T-LoRA 同参数对比。

### 10.2 风格 LoRA 推荐配方

| 参数 | 参考值 |
|---|---|
| network_dim / alpha | 64~128 / 64 |
| learning_rate | 5e-5 ~ 1e-4 |
| max_train_epochs | 12~50（图少取高） |
| num_repeats | 8（小数据集） |
| batch_size | 1 |
| lr_scheduler | cosine 或 constant_with_warmup |
| mixed_precision | bf16（5090） |
| 预览提示词 | 触发词 + 简单内容，别堆高分词 |

### 10.3 参考他人参数怎么映射（示例）

别人的检查点元数据（safetensors 里的 ss_* 字段）可直接参考：

| 别人字段 | 本项目对应 |
|---|---|
| ss_network_dim / alpha | network_dim / network_alpha |
| ss_learning_rate | learning_rate |
| ss_lr_scheduler | lr_scheduler |
| ss_lr_warmup_steps | lr_warmup_steps（0.1 = 10% 步数） |
| ss_num_epochs | max_train_epochs |
| ss_optimizer | optimizer_type（AdamW8bit 等） |
| ss_mixed_precision | mixed_precision |
| ss_timestep_sampling / logit / mode_scale | timestep_sampling / logit_mean / logit_std / mode_scale |
| ss_discrete_flow_shift | discrete_flow_shift |
| ss_huber_c / pseudo / schedule | huber_c / pseudo_huber_c / huber_schedule |
| ss_gradient_accumulation_steps | gradient_accumulation_steps |

> 注意：别人的步数 = 他们的图数 × repeats ÷ grad_accum × epochs，照搬时按自己的图数换算 epochs。

### 10.4 笔触/画风没学到的排查顺序

1. 确认训练用的数据是对的（日志 image_count）
2. 训练量：小数据集加 epochs（12 → 24）
3. 容量：dim 32 → 64 或 128
4. 提示词：去掉高分词再测
5. 数据：加到 30~50 张，画风统一，无水印

## 12. 常见问题排查表

| 症状 | 原因 | 解决 |
|---|---|---|
| `npm: command not found` | 系统没装 Node | 忽略，setup 脚本自带便携 Node |
| `git clone` RPC failed / early EOF | GitHub 直连断 | `source /etc/network_turbo` 或 ghproxy 镜像或下 zip |
| 无卡模式看不到 GPU | 用错模式开机 | 控制台切 GPU 模式，重新 SSH |
| 模型路径是 `/home/buxinzi/...` | base.toml 没改 | 见 3.5 |
| 日志 `No data found` | batch_size 太大，桶不满被丢弃 | `batch_size = 1` |
| `torch.compile ConstraintViolationError` | 长宽比杂，动态形状编译失败 | `torch_compile = false` |
| 图片数变成 73 / 38 等 | 新旧缓存混在一起 | 清 resized/lora 重跑预处理（6.4） |
| 预览图不出，只有 .pt | `sample_decode_inline=false` | 改成 `true` 并重新训练 |
| 训练“一直转圈” | 后台任务在跑 | Tasks 页看日志，别只看 spinner |
| 弹窗 Checkpoint Found | 有可恢复检查点 | 换数据选 Start Fresh |
| 参数改了界面没变 | 缓存 / 自定义文件覆盖 | Ctrl+F5；检查 `configs/custom/variants/` |
| SSH 连不上 | 端口变了 | 控制台看最新 SSH 命令 |
| 在本地 PowerShell 跑 Linux 命令报错 | 终端搞混 | Linux 命令只在云端终端跑 |
| SAM3 下载失败 | gated | 忽略，不影响训练 |
| fp16 训练 NaN | fp16 精度问题 | 改回 bf16 |
| AdamW8bit 报错 | bitsandbytes 兼容问题 | 改回 AdamW |
