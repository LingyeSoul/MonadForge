# MonadForge 全面上游同步与代理分工方案

## 目标与交付

完整吸收 `sorryhyun/anima_lora` 最新主线，保留 MonadForge 的 Vue WebUI、本地功能与当前未提交修复；新增模型和整理工具融入现有工作流，anime_tools 界面全部使用 Vue 原生组件实现。

当前核实上游为 `25eaf527`，本地为 `396f79b3`；执行开始时重新核对并固定上游 SHA。本地交付到 `codex/sync-anima-upstream-20261018`，分阶段提交，不推送、不创建 PR、不合并回 `main`。

V100 保留 Torch 2.10 训练兼容层；普通环境跟随上游 Torch 2.14。新版整理工具使用普通环境或独立环境，不承诺其在 V100 上具备 GPU 能力。

## 主代理监督与并行边界

主代理负责工作区保全、真实合并、共享接口、冲突处理、代码审查、集成提交和最终验收。最多同时安排 3 个子代理，按阶段复用：

| 阶段 | 可并行的子任务 | 主代理负责 |
|---|---|---|
| 基础整合 | daemon 兼容；适配器兼容；runtime/V100 与纯工具兼容 | 合并基线、依赖与锁文件、训练入口、配置链、进度协议 |
| 功能接入 | 整理 API 与执行包装；Vue 原生整理组件；Qwen/MOSS 模型模块 | 固定前后端接口，整合路由、模型上下文、任务持久化 |
| 验证收尾 | 非训练回归；前端交互验证；同步清单复核 | 审查证据、修复跨模块问题、完成最终提交 |

每项委派明确文件归属、接口、禁止修改区和验收条件。子代理不得自行暂存、提交、清理用户数据或扩大验证范围。共享文件由主代理统一编辑；子代理提出具体接入需求。主代理逐批审阅差异，验证通过或明确记录限制后再进入下一阶段。

## 基础同步与兼容实现

- 仓库外保存 HEAD、索引、当前差异、新增测试及 `.snow/`。现有修复在集成分支单独形成检查点；`.snow/` 不进入提交。模型、数据、缓存、输出和历史任务不作为升级清理对象。
- 保留现有 remotes，新增 `anima-upstream` 指向原始上游，不覆盖同名标签。结合完整文件树、提交历史和历次回退记录建立同步清单，确保普通 merge 不会遗漏已合并后又回退的能力。
- 进行真实合并并逐项解决冲突，不整树选择 ours/theirs。完整覆盖上游代码、文档和研究材料；本地适配器、量化、下载镜像、分阶段分辨率和恢复训练按完整调用链保留。

**依赖与 V100**

- 普通环境采用上游分组依赖、Torch 2.14 和固定版本 anime_tools，先隔离安装验证，再更新项目环境。
- anime_tools 要求 Torch ≥2.12，不能直接加入 V100 的 2.10 环境。将训练必需的纯文本、桶计算、路径遍历等无模型模块固定来源 SHA、保留许可证，经统一兼容门面调用，并做与上游的行为一致性测试。
- 统一运行环境选择：普通任务、V100 训练和整理任务使用明确配置的解释器；浏览器只能选择已登记的运行环境。任务持久化记录所用环境，缺失时明确报错。
- 安装器、更新器、daemon 和相关子任务共用环境识别。V100 更新不得执行会替换 Torch/CUDA/FlashAttention 的普通 `uv sync`；保留并核对原有指纹。
- 保留 V100 attention provider 的公开／私有入口兼容、dtype 与分派逻辑，不仅保留安装脚本。

**daemon 与训练协议**

- 采用 `anima_daemon` 统一实现，旧入口兼容转发；保留 WebUI sidecar、串行队列、续训和历史任务读取。
- 默认关闭上游启动时的历史任务自动清理，仅保留显式手动清理入口。
- 明确区分 `/unpause` 的暂停恢复与 `/continue` 的断点续训；旧 `/resume` 按状态兼容分派。暂停任务计入活跃 attempt，禁止重复续训；保存中、排队中和已完成任务不得误入续训。
- 合并两端 Job 字段并兼容读取 `rc/returncode`，保留签名、attempt、恢复和采样信息，不能读取旧记录后丢字段重写。
- 一并整合停止、暂停、状态保存、终态事件和采样事件，保持 WebUI、训练档案分析器及历史 JSONL 可读。Qwen/MOSS 不自动获得仅适用于 Anima 的续训语义。

## 模型与 Vue 原生整理工作区

**模型接入**

- 模型上下文扩展为 `anima | qwen21 | moss`，共用配置、预处理、测试、任务、看板和图库入口。
- 纳入最新 Qwen/MOSS 请求、缓存、生成和适配器能力；新增 `/api/moss`，沿用现有 schema、profile、预检查、任务和结果模式。
- 保留 Qwen 官方目录、分片、Comfy 单文件、自动空值、显式零与量化拒绝边界。各模型使用自身配置和缓存规则，结果绑定实际 job。
- MOSS 自动调参入口可以实现，但本次验收不得执行其中的训练步骤。

**整理工具接入**

- 在现有数据集页面实现原生编辑区域，覆盖 11 个阶段：缩放、自动打标、位置标注、校正、标签组移除、多视图审查、OCR、分组、SAM 遮罩、遮罩合并和导出。
- 实现版本梯级、标注差异、标签与子句编辑、OCR 框、遮罩叠加、分组与分析、建议审阅、应用与撤销、排除恢复、设置和导出状态；不能以生成阶段表单代替完整界面。
- 新增 `/api/curation`，复用 anime_tools 的 schema、请求校验、解析和底层处理函数，不使用其独立 JobManager。
- 新增受限 `curation-stage` 命令包装器，将预处理、主阶段和后续处理封装在一个 daemon 作业内；首错终止，取消覆盖整个进程树。
- 每个作业保存阶段、roots、workspace、参数、作用范围、步骤和报告路径快照。历史报告、应用和撤销使用该快照，不能读取当前页面所选数据集。
- 新整理 API 独立遵守已登记 roots 和路径边界；普通编辑写 workspace overlay，不复用旧图片浏览器直接写源标注的接口。位置子句通过官方语法解析，不能按逗号拆分。
- 导出保留“预览 → 审阅 → 应用”流程，明确展示源标注回写及过期 sidecar 清理。升级及验证本身不操作真实数据集。

## 验证、完成标准与记录

- 改动前记录相关基线失败；每批执行最小充分验证，最后运行一次审查后的非训练回归集合。
- 使用明确的测试文件和 node ID 白名单，排除 backward、optimizer step、真实训练、完整缓存和模型生成；修正测试命令覆盖排除标记的风险，不直接运行未经审查的全套测试。
- 模型相关检查使用 CPU、小型合成对象和临时数据，完整进程树置于 4 GiB 内存、swap 0 的限制内，不使用无限制并行测试。
- 重点覆盖配置优先级、当前修复、三模型隔离、旧权重元数据、Job 双读、暂停与续训分派、历史任务保留、取消、失败与进度传播。
- 整理工具用临时样本验证编辑、导出、源标注回写、清理、撤销及文件漂移拒绝，不触碰真实素材。
- 执行前端测试、生产构建和实际浏览器交互验证，检查模型切换、未保存状态、整理流程、任务结果及桌面／窄屏布局，保存截图和控制台证据。
- 主代理最终逐项复核同步清单与子代理差异，记录固定 SHA、保留与适配项目、迁移方式、通过结果、已知失败和恢复方法。
- 未执行的 Windows、ROCm、V100 实机检查及真实模型数值验收明确列出。只有完整能力整合及约定的非训练验证完成，才能宣布本次任务已完成；真实训练验收由用户负责。
